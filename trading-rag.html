The problem

The useful information already existed. Finding it was the hard part.

A trading educator had built up a large archive across Discord messages, videos, screenshots, daily commentary, and later reviews. Members could learn a lot from it, but answering a specific question often meant knowing where to look and manually piecing together information from several sources.

I wanted the archive to work more like a knowledgeable assistant: ask a normal question, have the system find the relevant material, and get an answer based on what the educator actually said.

Writing the answer

The final LLM receives a bounded set of retrieved evidence and turns it into natural language. It is not given free rein to make up missing facts.

Keeping answers trustworthy

The model answers from what the system actually found.

RAG is useful because the model does not have to remember this private archive from training. The system first gives it the relevant source material. The answer layer is then checked so substantive claims stay tied to that evidence.

✓

Evidence first. Retrieve relevant records before asking the model to answer.

✓

Bounded context. The answer model receives a finite evidence set rather than the whole archive.

✓

Validation. Answers that do not satisfy the grounding rules can be repaired or rejected.

✓

Fallbacks. If generation fails, the system can surface retrieved evidence instead of inventing an answer.

One extra challenge

Keeping the AI from making things up

LLMs can sound confident even when they do not have the right information. This system first finds relevant material from the archive and only then asks the model to answer. If the archive does not support a claim, the system should leave it out instead of filling in the gap.

Under the hood

Technical enough to be reliable, without making the user think about it.

The user experience is simple, but the retrieval path has safeguards underneath it: query interpretation, raw and rewritten lexical search, ranking, evidence selection, structured answer generation, and automated validation.

The current codebase also includes unit, integration, evaluation, and regression tooling so changes can be checked against known behavior instead of judged only by a few hand-picked demos.
